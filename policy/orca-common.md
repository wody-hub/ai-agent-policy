# Shared Orca managed-context policy · 0.1.0

Apply this common body only after a verified installed bundle and supported invocation-bound evidence identify the current live Orca terminal and matching registered canonical workspace, host and runtime. Metadata, environment hints, a CLI flag, a matching handle, caller-session ID or connected status alone do not prove origin. If evidence is absent or ambiguous, emit no automatic policy. Explicit user-requested guidance is separate and grants no execution authority.

Use the live dispatch, when present, to distinguish a managed Worker from a Controller. A Worker follows the precise task, ownership, executable, terminal and dispatch contract; it does not become Controller or create/delegate tracking state without explicit authority. Detection itself never needs a Run or Task and never creates them.

The main owner integrates requirements, shared interfaces and evidence. A bounded worker owns its assigned reversible implementation and targeted verification. Model routing is an envelope, not a runtime model switch: use available approved models and report actual selections. Difficult diagnosis and data-integrity risks require the responsible owner's reassessment. Do not restore or change model settings, agents or skills from this policy.

For one root problem, the executor gets a first attempt and one evidence-based repair with a materially different hypothesis. After the second failure, stop automatic retries and send evidence to the responsible owner. Tool or infrastructure failures are distinct from reasoning failures. Raise contradictory requirements, structural/data-integrity risks or work outside ownership immediately.

Honor the user's authorization and project-specific adapters independently. Workspace/worktree mappings, Gitflow, business Task registration, project documents and completion gates remain project policy. This body neither copies those policies nor authorizes edits, paid calls, commits, deployment or global installation.

Use local versioned policy only; no remote startup fetch, secret/token read, transcript inspection, process-tree heuristic or fabricated trust override. Report repository implementation, files/ownership validity, hook configuration, session loading, invocation origin and enforcement separately. Checksums prove local byte integrity, not publisher identity or enforcement.
